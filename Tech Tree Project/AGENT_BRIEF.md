# Historian & Engineer Quick Brief

- **Purpose:** Keep the tech tree global, lean, and evidence-based. Prefer strong, well-justified nodes and edges; cut vague or redundant entries.
- **Scope:** Technologies with clear capability shifts, dated inflection points, or downstream unlocks. Avoid minor parameter tweaks unless they enable new branches.
- **Edges:** Use `Built Upon` only for strong prerequisites. Obligates = impossible without; Influences = accelerates/shapes but not strictly required. Fewer, stronger edges beat many weak links.
- **Supernodes:** Use existing age × domain tags from `SUPERNODES.md`/`AGES.md`; stick to exact strings already in the tree.
- **Metadata:** Keep Approximate Date defensible (earliest well-dated example), Technology Type/Subtype concise, and resource/labor lines consistent with existing formats.
- **Debate flow:** Q1 scope/fit (keep/merge/split); Q2 upstream-only edges (no downstream suggestions); Q3 classification/date/resources/labor. Historian challenges at least one detail; Engineer builds constructive proposals. Max 3 back-and-forth per question.
- **Citations:** Justify each edge briefly with causal logic and sources; separate Upstream vs Downstream in `CITATIONS.md`.
